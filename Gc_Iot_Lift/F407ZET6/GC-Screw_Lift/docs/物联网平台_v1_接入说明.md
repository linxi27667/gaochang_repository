# 丝杆举升机物联网平台 v1 接入说明

本工程的物联网固件使用 STM32F407 的 96 位芯片 UID 作为设备唯一身份，不使用固定设备名作为 MQTT 路由依据。

## MQTT 配置

- Broker：`mqtt.gclift.net:1883`
- Client ID：`gc-lift-<chip_uid>`
- 上行：`gaochang/lift/v1/devices/<chip_uid>/up`
- 下行：`gaochang/lift/v1/devices/<chip_uid>/down`
- 产品型号：`double_post`

固件启动时会查询 DTU 保存的 Broker、Client ID、发布主题和订阅主题。任一项仍为旧配置时，会自动重新配置 DTU 并重连。

## 平台登记

首次安装时，从设备启动日志或上行 JSON 的 `chip_uid` 取得 UID，并在管理平台的设备登记中绑定该 UID 与目标双柱举升机。未登记 UID 的上行报文会被平台拒绝，这是平台的设备隔离机制。

## 数据和命令闭环

每个上行 JSON 都包含 `v:1`、`chip_uid`、`uid` 和 `product_type`。遥测、状态、高度和命令回执均通过同一个上行主题发送。

报文同时带有 `firmware_version` 与 `boot_id`，平台可据此记录当前固件版本和设备最近一次启动实例。

下行命令必须包含 `type:"command"`、本机 `target_uid` 和非空 `msg_id`。固件只接受 UID 匹配的命令；同一 `msg_id` 重复抵达时不会再次操作设备，而是重发第一次的回执。命令回执类型为 `command_response`，结果为 `succeeded`、`rejected` 或 `failed`。

远程锁机、解锁、管理员模式、清故障、管理员点动和维护完成仍使用已有权限与安全判断。`clear_alarm` 被映射为已有的管理员清故障流程，不能绕过防撞、限位或丝杆保护逻辑。

GC-Screw_Lift（F407ZET6）的能力边界和接线验收方法见 [接线与控制逻辑总览](接线与控制逻辑总览.md)。平台登记时应关闭蜂鸣器能力，且不要对该设备使用剪式机专用的 `set_config`、`get_config`、`reset_usage` 命令。
