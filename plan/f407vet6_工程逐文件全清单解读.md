# f407vet6 工程逐文件全清单解读

生成时间：2026-05-09 21:10:36

## 1. 我先把这个工程整体讲清楚
这是一个基于 STM32F407 + FreeRTOS 的双立柱升降控制工程。它的业务链条很清晰：按键产生动作意图，控制任务根据方向和状态发出电机动作，编码器脉冲提供高度反馈，平衡模块保证左右立柱不跑偏，安全模块负责碰撞、堵转和限位保护，W25Q 外部 Flash 则负责掉电后的参数与高度保存。

主线文件关系是这样的：
- `Core/Src/main.c` 负责把系统和模块都启动起来。
- `Core/Src/freertos.c` 创建 `Control_Task`、`Safety_Task`、`Key_Task`、`RS485_Task`。
- `Driver/Src/dri_motor.c` 是业务主状态机。
- `APP/Src/motor.c`、`APP/Src/encoder.c`、`APP/Src/balance.c`、`APP/Src/safety.c` 组成执行、反馈、平衡、安全四大闭环。
- `APP/Src/app_w25qxx.c` 负责掉电保存。
- `APP/Src/app_rs485.c` + `BSP/Src/bsp_uart_dma.c` 负责 RS485 DMA 通信。

## 2. 模块化理解
### APP
APP 层是功能逻辑层。这里不直接碰寄存器，而是围绕电机控制、按键、编码器、安全、Flash、RS485 去写业务规则。最关键的是 `balance.c`、`safety.c` 和 `app_w25qxx.c`。

### BSP
BSP 层是硬件抽象层。它把 SPI、UART DMA、W25Q 原始命令这些底层差异包起来，让 APP 层和 Driver 层不必关心 HAL 细节。

### Driver
Driver 层不是传统意义上的芯片驱动，而是任务驱动层。这里把 APP 层的功能组织成周期任务，真正让系统按 10ms、20ms 这些节拍运转。

### Core
Core 基本是 CubeMX 生成的启动和外设初始化层，包括 GPIO、DMA、TIM、USART、SPI、HAL Tick 和中断入口。

### 第三方
`Drivers`、`Middlewares/Third_Party/FreeRTOS`、`RTT_easylog` 主要是第三方库。它们很重要，但大部分不是你自己业务逻辑的核心。

## 4. 当前读码时发现的关键问题
- `APP/Src/key.c` 在 `MAX_KEY_NUM=2` 的情况下仍访问 `g_key[2]`、`g_key[3]`，这是越界。
- CMake 主工程没有完整纳入 RS485 / FIFO 相关源文件，构建链路和代码调用不一致。
- FreeRTOS CMake 路径写的是 `portable/GCC/ARM_CM4F`，但仓库里实际存在的是 `portable/RVDS/ARM_CM4F`。
- 碰撞中断注释写的是 falling，但 GPIO 现在配置成了 rising，需要和硬件接线核对。

## 5. 逐文件说明
下面这一部分覆盖工程内全部 `.c/.h` 文件。业务代码我写得更具体，第三方库按模块归类说明。

### APP
- `APP/Inc/app_rs485.h`：RS485 应用层头文件，定义初始化、发送、接收、缓冲查询与接收事件回调接口。
- `APP/Inc/app_spi.h`：SPI 应用层头文件，把 SPI1 和 W25Q 片选脚绑定成上层可用的 SPI_Bus 对象。
- `APP/Inc/app_w25qxx.h`：W25Q 应用层头文件，定义双槽存储结构、配置结构、高度存储结构和对外 API。
- `APP/Inc/balance.h`：双柱平衡算法头文件，对外暴露 Balance_Run。
- `APP/Inc/encoder.h`：编码器模块头文件，定义初始化、读数、清零和捕获中断处理接口。
- `APP/Inc/key.h`：按键与蜂鸣器模块头文件，定义按键状态机、命令结构体、引脚和去抖参数。
- `APP/Inc/motor.h`：电机控制头文件，定义方向、状态、双柱运行状态结构和启停 API。
- `APP/Inc/safety.h`：安全模块头文件，定义告警类型、碰撞/限位输入和安全检查接口。
- `APP/Src/app_rs485.c`：RS485 应用层实现，把 HAL UART DMA 操作和 FreeRTOS 同步机制封装为统一发送接收接口。
- `APP/Src/app_spi.c`：SPI 应用层实现，提供 SPI 初始化、片选控制、发送和收发适配。
- `APP/Src/app_w25qxx.c`：W25Q 应用层实现，负责参数双槽冗余加载/保存，以及双柱高度掉电保存恢复。
- `APP/Src/balance.c`：双柱平衡控制核心，根据左右柱脉冲差判定快柱并暂停，差值回到容差内后恢复。
- `APP/Src/encoder.c`：编码器中断累计实现，更新每个立柱的脉冲计数和最后脉冲时间。
- `APP/Src/key.c`：按键扫描和蜂鸣器控制实现，维护按键状态机并把结果映射到 g_command。
- `APP/Src/motor.c`：继电器式电机驱动实现，封装单柱和双柱的上升、下降、暂停、停止和急停流程。
- `APP/Src/safety.c`：安全策略实现，处理碰撞、堵转、上下限位和二次下降保护。
### BSP
- `BSP/Inc/bsp_spi.h`：SPI 总线抽象层头文件，定义总线句柄、GPIO 片选对象和底层函数指针。
- `BSP/Inc/bsp_uart_dma.h`：UART DMA 通用抽象头文件，定义句柄结构、底层操作集和 FIFO 对接接口。
- `BSP/Inc/bsp_w25qxx.h`：W25Q 底层驱动头文件，声明读 ID、读写、擦除等原始操作。
- `BSP/Src/bsp_spi.c`：SPI 总线基础实现，只有初始化、选中、释放片选这几项最底层操作。
- `BSP/Src/bsp_uart_dma.c`：UART DMA 通用实现，负责 DMA 接收、发送互斥、发送完成同步、出错恢复和回调桥接。
- `BSP/Src/bsp_w25qxx.c`：W25Q 原始协议实现，完成 JEDEC ID 读取、忙检测、页写、扇区擦除和跨页写。

## 6. 这一版文档怎么用
- 如果你是第一次接手这个工程，先读第 1 到第 4 节。
- 如果你正在改业务逻辑，优先读 `APP` 和 `Driver`。
- 如果你在排通信问题，顺着 `app_rs485.c -> bsp_uart_dma.c -> usart.c -> stm32f4xx_it.c` 这条链读。
- 如果你在排掉电保存问题，顺着 `app_w25qxx.c -> bsp_w25qxx.c -> app_spi.c -> spi.c` 这条链读。
